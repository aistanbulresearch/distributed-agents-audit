## 1. Question

Among the quantitative assertions in the released evidence ledger that the pre-registered
extractor recovers and that can be evaluated, what share do not match the
differential-expression data the agents are documented to have analysed: the reference file
named as the agents' input in the authors' own task configuration (section 2, which also
states how far that identification is verified)?

**Scope of every H1 statement.** H1 measures *extracted, evaluable assertions* only. It makes
no claim about assertions the extractor misses, about unresolvable or out-of-scope
assertions, or about the ledger as a whole; the extraction-quality results (section 5) are
reported beside the primary measure so a reader can judge coverage.

We call this **data consistency**: whether stated numbers reproduce from the data. It says
nothing about the biological correctness of any finding.

The report-generation prompt instructs: "Do not invent references, evidence, genes,
statistics, or mechanistic links" (Methods p3). The paper reports no data-consistency rate,
so H1 is a measurement, not a test of a published claim.

## 2. Data and reference equivalence

- **Assertions:** `ledgers/evidence.csv`, column `statistics`, release `shi`, upstream commit
  `c20445d`.
- **Reference data:** `perturbai/wholebrain_crispr_atlas`, revision
  `a7c65dc0a64da4bd47cf6ef5f4dec6c7ef745e87`, file
  `analysis/2603_shi_manuscript/diff_expr_genes/wilcoxon_de_results_group_name_final_data_no_multi_guide_cells.parquet`,
  SHA-256 `cade64a236e3707e91c289bae32282e8b919276760223e581af2342232bcb969`. Its filename is
  the `input_parquet` of the upstream literature-flags task, and its revision date
  (2026-03-20) precedes the report runs (May–July 2026). Filename and date do not by
  themselves prove it is the agents' input; the equivalence check below tests that for the
  18 released targets only.
- **Column mapping:** logFC → `logfoldchanges`; score / z → `scores`; p / nominal p →
  `pvals`; FDR / q / padj / adjusted p → `pvals_adj`; perturbed cells → `n_pert_matched`;
  controls → `n_ctrl_matched`.

**Equivalence check (run first, before any report statistic is compared).** For the 18
targets in the upstream file `data/inputs/biology/differential_expression.parquet`:
- the set of `(gene_target, group_name, names)` keys must be identical;
- `n_pert_matched` and `n_ctrl_matched` must be equal on every row;
- `logfoldchanges`, `pvals`, `pvals_adj` and `scores` must agree within relative tolerance
  1e-6 (absolute 1e-12 near zero) on at least 99.9% of rows.

**What the result is called.** No released file binds the full reference to the report
generation runs (their configuration is in the unreleased `build/` module). Therefore:
- The primary measure over all 1,946 targets is always reported as **agreement with the
  selected reference (revision `a7c65dc`)**, whatever the equivalence check shows.
- The label **"consistency with the agents' input"** is used only for the 18 targets the
  equivalence check verifies, and only if it passes; it is never extended to other targets.
- *If the check fails:* the 18-target label is not used, the failure details are reported,
  and provenance is investigated and logged. The reference is not switched after report
  statistics have been compared.

## 3. Unit of analysis and extraction grammar

The unit is one **atomic assertion**: one reported number, bound to a target, a cell-type
context and, for gene-level values, a gene.

Extraction is done by `audit/lib/h1_extract.py`; `tests/test_h1_extract.py` defines the
grammar by example, using verbatim ledger phrasings (including every case raised in review).
They use the `statistics` text and two vocabularies only: the 23 cell-type labels and the
distinct gene names (`names`) of the reference file. No DE value column is read.

**Processing order.** Normalise numbers (Unicode minus; `3.1 × 10^-5` → `3.1e-5`) → mask every
cell-type label → split sentences (not after `vs.`, `e.g.`, `i.e.`, `ca.`, `approx.`, `Fig.`,
`al.`, `cf.`) and clauses (`;`) → mask out-of-scope spans, numeric ranges first → match
in-scope patterns in a fixed order, masking each match so no number is used twice.

**Cell-type resolution, in this order:**
1. the nearest label earlier in the same clause (a colon does not stop this search, so
   `151 TH Prkcd Grin2c Glut: 135 perturbed …` binds the label);
2. the first label later in the same clause, **without crossing a colon** (so in
   `Only 6 Ap3b1 rows had FDR<1.0: Fam169a … in 005 L4-5 IT CTX Glut` the count is not
   bound to 005, while Fam169a's values are);
3. for gene-level values only: the nearest label earlier in the same sentence;
4. the row's `cell_type` field;
5. otherwise none.
The source (`clause`, `sentence`, `row`) is recorded. Regression: Ap3b1/E004.

**Gene resolution.** Cell-type labels are masked first, so gene symbols inside labels
(`053 Sst Gaba`, `052 Pvalb Gaba`, `151 TH Prkcd Grin2c Glut`) are never bound (regression:
Grm6/E004). Equalities bind to the nearest preceding measured-gene token in the sentence.
**Inequalities bind only to a gene token directly before the statistic** (optionally followed
by "self" or "target"); otherwise they are `unresolved_context`, so aggregate thresholds
(`overall FDR<0.05`) never become gene assertions.

**Assertion types in scope:**

| Type | Examples | Recomputed as |
|---|---|---|
| A. Gene value | `Auh score -5.116, logFC -0.571, p=3.12e-7, FDR=0.00544`; `q 0.0318` | the value for (target, cell type, gene) |
| A′. Gene inequality | `Ahdc1 FDR<0.05` | whether the inequality holds |
| B. Cell counts | `145 perturbed cells versus 20,353 controls`; `164 Clec16a cells versus 23,679 controls`; `135 perturbed versus 23,679 controls`; `149 Rara cells`; `8,277 controls`; `n_pert_matched 64` | `n_pert_matched`, `n_ctrl_matched` |
| C. Significant-gene count | `37 genes at FDR<0.05`; `0 FDR<0.05 genes`; `No FDR <0.05 genes`; `112 rows had p < 0.001`; `6 Ap3b1 rows had FDR<1.0` | rows below the stated threshold |
| D. Totals | `371818 Wilcoxon rows`; `rank 1 of 17,443`; the N in `1/17443 genes` | row count for the bound scope |
| E. Minima | `min FDR=0.602440`; `minimum nominal p = 1.13e-05` | minimum over the bound scope |

Regressions: Bcas3/E005 (threshold-first zero counts; "perturbed versus" without "cells"),
Clec16a/E004 (paired count naming the target), Fezf1/E003 (ranges).

**One primary interpretation per assertion.** Counts (C, D) and minima (E) are recomputed
under a single primary interpretation, fixed by the text:
- *Unit:* `rows` → gene × cell-type rows; `genes`/`DEGs`/`transcripts` at cell scope → rows
  of that cell type; at target scope → distinct genes.
- *Self inclusion:* resolved once per count from the count's own text plus its lead-in (from
  the previous extracted span in the same clause, or the clause start), so a qualifier of an
  earlier count never carries over. `non-target`, `non-self`, `non-<Target>` (e.g.
  `non-Ap3b2`), `excluding the target / <Target>`, `other than the target / <Target>` → the
  target's own transcript excluded; `including the target / <Target>` → included; otherwise
  included (literal reading). The same resolution applies to the count's denominator (the N
  in `k/N` and in `among N tested`). Recorded as `self_inclusion`. Regressions: Dnajc5/E006,
  Ap3b2/E002.
- *Restricted populations:* a count, total or minimum whose lead-in names a restricted subset
  (`selected`, `listed`, `prespecified`, `candidate`, `chosen`, `curated`, `panel`, `module`,
  `these`, `those`) is `out_of_scope` (reason `subset_scope`): the subset cannot be
  reconstructed from the DE data, so it is neither bound to a nearby cell type nor compared.
  Regression: Ndufv1/E008. The word list is how the extractor detects subsets; it does not
  limit the rule. For the annotation key, a count whose text explicitly identifies a
  restricted population (e.g. "88 rows covering Mcf2l, Rhoa, Rock1, and Rock2") is out of
  scope as a subset count even without one of these words; an extractor that keeps such a
  count in scope makes an extraction error, counted by the quality gate (section 5).
- *Scope:* the bound cell type if any; otherwise the whole target. A gene token directly
  before "minimum" restricts E to that gene.

Where the text is genuinely ambiguous — `genes` at target scope, unstated self inclusion, or a
cell type that came only from the row field — the alternative interpretation (rows instead
of distinct genes; self excluded; target scope instead of the row's cell type) is computed
as a **sensitivity analysis** and reported separately with its own counts. It never changes
the primary outcome.

**Out of scope** (counted, not evaluated): counts over restricted subsets (above); every
numeric range (`0.895-0.917`, `23-191`,
`-0.21 to -0.4`, "ranged from", "between … and"), correlations and similarities (r, rho,
cosine), medians, means, maxima, approximations (`~`, "approximately"), recurrence across
cell types or signatures (a clause containing `k/N had`, `k of N cell types`, `in k/N`), and
any clause naming another perturbation (`Tsc1 perturbation` in a Tsc2 row).

**Outcome categories.** `match`; `mismatch`; `context_not_in_data` (target × cell type or gene
absent from the reference); `unresolved_context` (no cell type or gene could be bound);
`out_of_scope`.

## 4. Matching rule

Implemented in `audit/lib/h1_match.py`; tests in `tests/test_h1_match.py`.

- **Decimals:** the unit is one step of the last written digit (for scientific notation, of
  the last mantissa digit, times the power of ten). A recomputed value matches if it
  **rounds** to the reported value (|recomputed − reported| ≤ unit/2) or **truncates toward
  zero** to it (`[reported, reported + unit)` for non-negative reports,
  `(reported − unit, reported]` for negative ones). Fixed by tests: reported `p=0.001` does
  not match 0.0001; `FDR=1.0` does not match 0.91 but matches 0.96; `3.12e-7` matches
  3.1249e-7 but not 3.13e-7.
- **Signs** follow from the intervals: a logFC or score with the wrong sign does not match.
- **Bare-integer probabilities** (`FDR=1`, `p=0`) are read with one decimal place.
- **Counts:** exact equality.
- **Inequalities:** evaluated strictly as written (`<` is strict).

## 5. Extraction quality check (before comparison)

Done after the freeze and before any report statistic is compared. Its annotation is
produced before the freeze.

- **Samples (frozen procedure, `audit/lib/h1_sampling.py`).** Population: non-control
  evidence rows with a non-empty `statistics` field (17,783 rows), identified by
  `(target_gene, evidence_id)` and put in canonical ascending order. Sample 1:
  `random.Random(20261023).sample(population, 150)`, without replacement. Reserved validation
  sample: `random.Random(20261024).sample(population minus sample 1, 150)`, so the two never
  overlap. Both samples' row identifiers, the population size and the SHA-256 of the
  canonical population list are published at the freeze as `registrations/H1_samples.json`
  (drawn by `audit/scripts/h1_draw_samples.py`; a rerun reproduces the file byte for byte).
  Both samples are annotated and their keys frozen before the freeze (below); the reserved
  sample's key is used only if a re-check is needed.
- **Annotation (dual, with human adjudication), both samples.** Each sampled field is
  annotated with every in-scope assertion and these fields: quantity, relation, value text,
  cell type, gene, scope, unit, self inclusion, threshold quantity, threshold relation,
  threshold value.
  - *Packets.* Built by `audit/scripts/h1_build_packet.py` from the template
    `audit/templates/h1_annotator_packet.md`, the cell-type labels, the current section-3
    text (unchanged since revision 10; frozen file `H1_section3_rev10.md`, which differs from
    revision 8's only by the restricted-population rule) and the sample's 150 fields in sample order. Both
    annotators of a sample receive the same packet except for the output file path written
    into it. The script reproduces annotator A's earlier sample-1 packet byte for byte from
    the revision-8 text (SHA-256 `5dcfc47957f2eb05cd62cfa982b1754474494c1a925f2b0fa67f53bbbfebc425`),
    which shows the builder is faithful. Every packet's SHA-256 is recorded. If section 3
    changes after the annotation, the annotation is rerun with the changed text.
  - *Annotators.* Fresh agent sessions: annotator A (Fable 5.1, high) and annotator B
    (Opus 5.5, high), each for both samples, all four runs with revision-10 packets. Neither
    sees the extractor code or output, or the other annotator's work. Each receives the same
    wrapper instruction (read only the packet; write only the named output file).
    Annotator A's earlier sample-1 run (revision-8 packet) is kept as a historical artifact;
    it served only the owner's 30-field check.
  - *Sample 1, owner-checked fields.* For the 30 fields drawn by `owner_check_sample` (seed
    `20261025`, before any annotation existed), the owner checked annotator A's work. The
    resolution applies section 3's literal rules to the owner's notes, except where the owner
    identified an explicitly restricted population (field Il1rapl1/E014), which is out of
    scope as a subset count (the owner's decisions on the check, labelled DC-27 and DC-29 in
    the code). Concretely: rows the owner marked correct or conditionally
    correct are kept, rows marked wrong are dropped (all 20 in Atf6/E006, statistics of
    another perturbation), the Il1rapl1/E014 zero count is dropped, and the owner's missed
    rows are added only where section 3 resolves them (Eif4h/E010, Htr1a/E005 with its
    target-scope minimum adjusted p 0.693, Pde1c/E004); missed rows that section 3's literal
    rules cannot bind (Atp2b2/E007, Itm2b/E006, Rpgrip1l/E006) are not added. These rules are
    encoded in `audit/scripts/h1_assemble_keys.py`. This resolution is final for those
    fields.
  - *Pairing.* For the other 120 fields of sample 1 and all 150 fields of sample 2,
    annotator A's and B's assertions are paired by the correspondence rule below. A field is
    **fully agreed** if every assertion of either annotator has a counterpart agreeing on
    every comparison field (two empty annotations are fully agreed). Every other field is
    **partially disagreeing**.
  - *Self-inclusion labels in the key (revision 13).* Section 3's resolution is unchanged:
    with no qualifier the target's own transcript counts as included (the literal reading of
    the primary analysis; the sensitivity analysis excludes it). The key labels the three
    cases as follows: `exclude` for an exclusion qualifier; `include` only when the count's
    own text or lead-in says "including the target/<Target>"; `unstated` when there is no
    qualifier. These are the labels the extractor uses and the case section 3 calls
    "unstated self inclusion". The codebook offered `exclude`, `include` or `unstated` "per
    Section 3" without saying which label the no-qualifier case takes; in sample 2,
    annotator A wrote `unstated` and annotator B wrote `include` for 96 such counts in 40
    fields, none of which contains an explicit "including" phrase (in sample 1 both used
    `unstated`). The convention was fixed after the annotations were returned, before any
    adjudication, and without any extractor output; because section 3's reading did not
    change, the annotations are not rerun. Field classification, the adjudication set and the
    agreement-audit draw are computed from the raw files, so the 35 sample-2 fields that
    disagree only on this label are still adjudicated in full; the convention is printed in
    the adjudication form. Both versions are shown to the owner with the convention already
    applied (`include` read as `unstated` where the field has no explicit "including"
    phrase), so the annotators' label habits cannot reveal which one is X (review round 13).
  - *Fully agreed fields* enter the key as annotated, subject to the agreement audit below.
  - *Whole-field adjudication of partially disagreeing fields.* The owner reviews every
    partially disagreeing field **in full** against section 3: the disagreeing assertions,
    the agreed assertions in the same field, and any in-scope assertion that both annotators
    omitted. The owner sees the raw text and both versions labelled X and Y, with A's label
    per field from `xy_assignment` (`audit/lib/h1_sampling.py`; seeds `20261026` for sample 1,
    `20261028` for sample 2), so the owner does not know which annotator wrote which. The
    owner's ruling on the whole field enters the key. Section 3 governs rulings, and an
    explicitly identified restricted population is out of scope as a subset count even
    without one of section 3's subset words. Completion and every correction are recorded;
    the freeze waits until all partially disagreeing fields of both samples are reviewed, and
    if this cannot be completed, H1's primary measure is reported as **inconclusive**.
  - *Agreement audit.* Two annotators can share an error. For each sample the owner also
    checks fields where A and B agreed on everything (both found nothing counts as agreement):
    20 such fields drawn by `agreement_audit_sample` (seeds `20261027` and `20261029`; all if
    fewer than 20), excluding sample 1's 30 owner-checked fields. Errors found are corrected
    in the key, and the error rate among audited agreed fields is reported with its Wilson
    interval.
  - *Agreement-audit failure rule (fixed before the audit runs; labelled DC-33 in the forms
    and code).* If the owner finds even
    one error in a sample's audited agreed fields, the owner reviews **all** remaining agreed
    fields of that sample, correcting errors, before the key is frozen; the freeze waits
    until this is complete. If it cannot be completed, H1's primary measure is reported as
    **inconclusive**, because the key cannot be established as trustworthy.
  - *Blinding.* The owner never sees extractor output for either sample before the key of
    that sample is frozen.
  - *Reported:* A–B agreement before adjudication (share of assertions agreed on all fields,
    and share of fields fully agreed), both from the raw files and with `include` read as
    `unstated` for counts in fields without an explicit "including the target/<Target>"
    phrase, the owner's agreement with A on sample 1's 30 checked
    fields, the number of whole-field adjudications and the corrections they made (including
    to agreed assertions and shared omissions), and the agreement-audit error rate, per
    sample.
  - *Key assembly.* Each field's key comes from exactly one source: the owner's check
    (sample 1's 30 fields), the whole-field adjudication, the agreement audit, the full review
    of remaining agreed fields when the failure rule applies, or, for agreed fields no review
    covered, the annotators' identical annotation under the label convention.
    `audit/scripts/h1_assemble_keys.py` re-checks every filled form against the raw files
    (each form covers exactly its selected fields; no displayed row altered; every resolved
    assertion fits the codebook) and records the source of every field.
  - *Files published at the freeze:* the packets, the section-3 files (revision 8 for the
    historical sample-1 run, revision 10 for the four dual runs) and the template; both
    annotators' raw files for both samples and the historical revision-8 file; the owner's
    check; the filled adjudication, agreement-audit and full-review forms; the pairing,
    tally and key-assembly records; and the resolved keys
    `registrations/H1_annotation_sample1.jsonl` and
    `registrations/H1_annotation_sample2.jsonl`.
- **Correspondence:** one-to-one within an evidence row, by normalised value text (thousands
  separators, sign and Unicode minus normalised), in order of appearance.
- **Measures:** *recall* = corresponding pairs / annotated in-scope assertions; *precision* =
  corresponding pairs / extracted assertions; *binding accuracy* = share of corresponding
  pairs in which **every** comparison field agrees: quantity, relation, value text, cell
  type, gene, scope, unit, self inclusion, threshold quantity, threshold relation, threshold
  value. Implemented in `audit/lib/h1_quality.py`; `tests/test_h1_quality.py` checks that
  corrupting any one of these fields fails binding.
- **Intervals:** each measure is also reported with a 95% interval from the frozen cluster
  bootstrap (section 6) over annotated fields, because extraction errors cluster within a
  field. Extraction errors (extracted assertions without a counterpart plus misbound pairs)
  are reported as a count. The acceptance criteria below use the point estimates.
- **Acceptance criteria:** recall ≥ 0.90 overall and ≥ 0.80 for every assertion type with at
  least 20 annotated instances; precision ≥ 0.95; binding accuracy ≥ 0.95.
- **If a criterion fails:** the parser is corrected; the corrected code is committed, its
  commit hash and file hashes are published in `registrations/H1_deviations.md` together with
  the reason, and only then is it evaluated, once, on sample 2 against sample 2's key frozen
  at the freeze. No one involved in sample 2's annotation or adjudication sees sample 2's
  extractor output before that evaluation. If it fails again, H1's primary measure is
  reported as **inconclusive**: the mismatch share is shown only descriptively, next to the
  failed criteria. There is no further retry.

## 6. Primary measure

**Mismatch share** = mismatch / (match + mismatch), over extracted assertions of types A–E
for the 1,946 non-control targets, under the primary interpretation of section 3. Only
assertions with outcome `match` or `mismatch` enter; every other category is reported as a
count.

**Interval method (frozen; `audit/lib/h1_stats.py`).**
- Estimator: pooled ratio, Σ mismatch / Σ (match + mismatch) over targets.
- Clusters: targets with at least one evaluable assertion; targets without one are excluded
  before resampling, so no resample has a zero denominator.
- Resampling: 10,000 resamples of the clusters with replacement, drawn by
  `random.Random(20261023).choices` over cluster indices, the ratio recomputed on each.
- Interval: percentile, at the 2.5% and 97.5% quantiles with linear interpolation between
  order statistics (Hyndman–Fan type 7).
- A synthetic regression pins the interval this method gives (100 targets, one with 30/100
  mismatches: [0, 0.009]), so no other construction can be substituted after the freeze.

**No verbal interpretation bands.** The result is reported as a number with its interval,
never as a verbal grade. Interpretation belongs to the paper's discussion, made with all of
the following on the table.

**Reported together with the primary measure:**
- counts of every outcome category (section 3);
- the extraction-quality results of section 5: recall, precision and binding accuracy with
  their field-level intervals, recall by type, and the extraction-error count;
- the post-comparison check below;
- the sensitivity analysis of section 3;
- the label rule of section 2 (full corpus: agreement with the selected reference; 18 verified
  targets: consistency with the agents' input, only if the equivalence check passes).

**Post-comparison check.** Mismatches are identified by `(target_gene, evidence_id, start
offset of the assertion in the statistics text, quantity)` and put in canonical ascending
order; all of them are checked if there are at most 100, otherwise
`random.Random(20261023).sample(mismatches, 100)`, without replacement (`audit_sample` in
`audit/lib/h1_sampling.py`, frozen and tested before any comparison). Each is checked by hand
and classified as genuine mismatch or extraction error. With M mismatches, N evaluable
assertions, `a` audited mismatches and `e` of them extraction errors, three supplemental
figures are reported under these fixed labels (`audit/lib/h1_stats.py`, tested, including a
synthetic case with more than 100 mismatches):
- **audited error share:** e / a, with its 95% Wilson interval;
- **confirmed-error removal:** (M − e) / (N − e). Only hand-confirmed errors are removed; no
  extrapolation to unaudited mismatches;
- **extrapolated:** with r = e / a, (M − M·r) / (N − M·r), with bounds obtained by putting the
  upper and lower limits of r's 95% Wilson interval into the same formula (the share falls as
  r rises, so r's upper limit gives the lower bound).
When every mismatch is audited (M ≤ 100) the last two coincide. A zero denominator, or
`a` = 0, is reported as "undefined". None of these figures replaces the primary measure.

## 7. Secondary measures (exploratory)

Reported as exploratory, with no inference attached to any one of them:
- mismatch share by assertion type and by statistic (logFC, p, FDR, score, counts);
- by the confidence and `literature_status` of the findings citing the evidence row;
- for reports that differ between the June snapshot and the release vs those identical;
- for the 100 safe-target control reports, separately;
- distribution of mismatch share per target.

## 8. Exclusions

- Control targets (`Safe_target_*`) are excluded from the primary measure and reported
  separately.
- `context_not_in_data`, `unresolved_context` and `out_of_scope` assertions are excluded from
  the primary denominator and reported with counts.
- Any other exclusion after the freeze is a logged deviation.

## 9. Implementation after the freeze

The comparison script (`audit/scripts/line_h1.py`) is written after the freeze. It may only
call the frozen extractor and matcher and implement sections 2, 5 and 6 as written. Any
choice it has to make beyond them is logged as a deviation.

2. **Freeze manifest** `registrations/H1_freeze.json`: the SHA-256 of every artifact above,
   the SHA-256 of the reference DE file, the upstream pin, and the commit hash of the code.
3. **Replay before publication.** A fresh clone of the frozen branch, with the upstream
   submodule initialised at the pin, runs `audit/scripts/h1_replay_freeze.py`: the manifest
   and reference file are verified, and every annotation generator is rerun and must
   reproduce the frozen samples, packets, sheets, blank forms, records and keys byte for byte.
   Registration files keep their exact bytes in Git (`.gitattributes`).
4. **Commit, tag and push** the artifacts and manifest (annotated tag `prereg-H1-v1`), then
   request an archival snapshot of the public repository from Software Heritage and record
   the returned snapshot identifier in the repository's freeze log. The Software Heritage
   snapshot provides an independent, third-party date that the repository cannot rewrite.
5. **Guard** (`audit/lib/freeze_check.py`). Before computing anything, the comparison script
   aborts unless all of the following hold:
   - the local freeze manifest has the SHA-256 stated in the freeze claim (tag, commit,
     manifest path and hash), and every artifact and the reference file (bound in the manifest
     by its input key and SHA-256) match it byte for byte;
   - querying Software Heritage live, the latest complete visit of the public repository
     contains the annotated tag `prereg-H1-v1`; the tag points to the claimed commit; the
     manifest archived at that commit has the claimed SHA-256; and the visit is not dated
     before the tag.
   A recorded snapshot identifier is not accepted on its own: the archive is queried for the
   claimed tag at run time, so a stale or unrelated snapshot, a moved tag or a replaced
   manifest fails (each covered by a test). The verification receipt (snapshot, visit date,
   release, commit, tag date) is written into the run's output. For publication, the earliest
   archive visit containing the tag is cited as the freeze date.

Revisions after the freeze are new versions (`registrations/H1_v2.md`, tag `prereg-H1-v2`)
published the same way, with a stated reason; results computed under an earlier version
remain reported.
